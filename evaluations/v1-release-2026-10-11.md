# v1.0 learning-demo evaluation and release decision

## Decision and scope

On 2026-10-11 the owner explicitly chose **Release a learning demo with documented
limitations** rather than retaining the stricter answer-quality release gate.
This report records that acceptance; it does not relabel failed quality checks as
passes. v1 covers text ingestion, retrieval and generation. OCR, hybrid search,
reranking and agentic workflows are not claimed.

## Final implementation checks

- 90 automated tests passed in 6.035 s on Windows/Python 3.12.
- Routing matrix covers `difference of`, `difference between`, `contrast`,
  `differentiate`, numbered chapter pairs, filenames and common table follow-ups.
  Topic comparisons using PDFs remain separate from document profiles.
- Missing requested chapters do not silently compare a smaller subset.
- Named-chapter summaries select the matching source, not the full collection.
- Comparison evidence references sentence IDs from the source context. The app
  resolves exact text spans and rejects invalid references, wrong-source IDs and
  unsupported acronyms/hyphenated terms. These are mechanical checks, not entailment.
- Missing cells get one source-isolated repair attempt with validation feedback.
  Successful cells are never overwritten. Complete profiles add no repair calls.
- Table-only follow-ups reuse final cells and evidence without retrieval/model calls.

Tests include upload replacement/removal, clear chat, retries, collection/session
isolation, interrupted streams and bounded regeneration. These are not load tests.

## Quality review — important qualifications

Answer coverage was reviewed across the run; selected claims were checked against
their excerpts. This was not an exhaustive independent claim-by-claim audit and
no overall accuracy percentage is asserted.

| Cases | Review finding |
| --- | --- |
| 1–8 factual | Answers cover intended OSI, UDP, TCP, ports, flow control, VLAN and CIDR facts; model prose can inherit incorrect source explanations. |
| 9–12 follow-ups | Correctly resolve the preceding topic; citation membership passes. |
| 13 retry | Complete source-scoped comparison; incorrectly groups Ethernet cables with connected devices. Exact spans alone do not prevent this category error. |
| 14–16 summaries | Cover all three PDFs; long combined summaries contain overgeneralized relationships and unqualified source claims. |
| 17 named summary | Full run included other chapters; final scope correction and targeted rerun restrict evidence to Chapter 3. |
| 18 six bullets | Six bullets cover the collection; semantic generalization remains possible. |
| 19 document comparison | Complete, source-owned cells; shared ideas are implicit in aligned features rather than a separately verified synthesis. |
| 20–24 topic comparisons | Cover requested pairs/layers; source contradictions and model interpretation require review. No automatic factual-truth verdict. |
| 25 chapter subset | Correct two-chapter scope and complete cells, but broad sampling can focus too narrowly on introductory pages. |
| 26 word limit | Three chapters, 146 prose words; some general terms remain broader than selected support. |
| 27–30 absent information | All explicitly abstain without inventing personal information. |

Earlier selected audit: six supported and two partial claims, documented in
`citation-audit-2026-10-11.md`. That sample is not an overall accuracy score.
Chapter 2's OSPF descriptions also conflict internally. RAG source fidelity is not
external fact verification. Original PDFs were not independently fact-checked.

Two experimental grounding pilots were rejected: requiring copied quotes and
then full content-word overlap caused excessive missing cells. The shipped
sentence-ID selection avoids requiring the model to reproduce exact quote text;
it does not claim to solve semantic correctness.

## Cloud evidence and remaining validation

The owner demonstrated the live app, uploads, comparisons and retries in screenshots.
Normal/incognito sessions with different documents were manually probed for the
other session's facts; both abstained. This is a smoke check, not a security proof.
Earlier owner-supplied Cloud logs showed 290 OS pages/295 chunks indexed in 19.786 s,
including 8.088 s extraction and 11.487 s embedding. Process RSS after indexing was
943.22 MB. Those are whole-process snapshots, not peak RAM or per-user allocation.

Final-build Cloud verification, controlled concurrent load tests and reliable
peak-memory measurement remain unperformed. The learning-demo release accepts
these limitations; production deployment would require further work.

## Publishing

Publish as v1.0 **learning demo**, preserve warnings in the UI and documentation,
and do not describe it as hallucination-free, exhaustive, production-ready,
agentic RAG, or an automatically fact-verified tutor. The release notes and git
tag preserve the basic baseline for later advanced-RAG evaluation.
